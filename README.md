# minoom미눔

3D 온라인 투룸 하우스 v0.1

독립 신규 프로젝트. 기존 프로젝트/저장소를 수정하거나 배포하지 않았습니다. 유료 API와 유료 3D 에셋을 사용하지 않습니다. 승인된 무료 CC0 에셋을 포함합니다. React 19, TypeScript, Vite, Three.js, React Three Fiber, drei, Zustand, Supabase로 구성했습니다.

## 실행

Node.js 22.12 이상 권장.

```sh
cd /workspace/two-room-home
npm ci
npm run dev
```

Vite가 출력하는 주소를 엽니다. `npm run build`는 `dist/`를 생성하고 `npm test`는 충돌 및 배치 규칙 테스트를 실행합니다. 네트워크가 차단된 환경에서는 패키지 설치 접근이 필요합니다.

## 로컬 체험

환경변수 없이 바로 실행됩니다. 온라인 미연결 배지가 표시되며 가상 접속자는 없습니다.

- PC는 화면 클릭 → 마우스 잠금, 마우스 시야 회전, WASD 이동, E 이용, ESC로 메뉴 조작. 잠금이 지원되지 않으면 드래그 방식으로 전환하고 안내합니다.
- 모바일: 왼쪽 원을 드래그하여 이동, 가구나 UI가 없는 화면을 드래그하여 시점 회전, 이용하기 버튼.
- 소파/의자/침대 가까이에서 이용하기. 다시 누르면 안전한 옆 공간으로 일어납니다. 문과 조명에도 같은 버튼을 사용합니다. 문이 가장 가까운 경우 문을 우선 이용합니다.
- 조감도 보기: 궤도 카메라로 집 전체 확인. 화면 안의 인테리어 하기를 누르면 가구를 선택·편집할 수 있습니다. 편집 끝내기는 조감도로 돌아갑니다.
- 인테리어 편집: 가구 클릭 후 위치·회전·크기 슬라이더. 미리보기 후 배치 저장. 벽/가구 충돌 시 저장 불가. 취소 시 원래 배치 유지.
- 컬렉션: 사진 등록, 종류 및 미터 단위 크기 입력, 기본 3D 또는 사진 보관 또는 GLB 선택. 같은 가구를 여러 번 배치할 수 있습니다.
- 사진만 보관한 가구는 배치할 수 없습니다. 기본 모델은 원본 사진과 다릅니다. 사진에서 3D 생성 기능은 없습니다.
- 로컬 저장은 localStorage입니다. 브라우저별로 분리되며 다른 기기와 공유되지 않습니다. 저장 용량 초과는 오류로 표시하며 기존 상태를 유지합니다. 특히 GLB는 작은 파일로 체험하세요.
- 업로드 사진은 폼에서 미리 볼 수 있습니다. 모바일 파일 선택기는 기기에서 제공하는 사진 촬영/앨범 메뉴를 사용합니다.

## 무료 Supabase 설정

1. 별도의 새 Supabase 프로젝트를 만듭니다. SQL Editor에서 `supabase/001_home.sql`을 한 번 실행합니다. 기존 프로젝트에 적용하지 마세요.
2. `.env.example`을 `.env`로 복사합니다. 프로젝트 URL과 공개 anon/publishable 키를 지정합니다. **service_role 키는 넣지 않습니다.**
3. Authentication에서 Email 로그인을 활성화하고 Site URL 및 redirect URL에 사용 중인 앱 주소를 등록합니다. 가입 확인 메일 정책에 따라 이메일에서 확인 후 로그인합니다.
4. 개발 서버를 재시작합니다. ‘로컬 데모’ 버튼 → 함께 살기에서 각자 별도의 이메일 계정을 등록합니다.
5. A: 새 집 만들기 → 초대 코드 발급. B: 코드 입력 → 초대 수락. A는 한 번만 집을 만듭니다. 각 계정은 하나의 집에만 연결되며 최대 두 명입니다.
6. 두 기기에서 내 집 접속. 위치·행동·감정은 private Broadcast(10Hz), 접속은 Presence, 영구 배치는 homes 행의 JSONB와 Realtime postgres_changes로 공유합니다. 원격 위치는 프레임에서 보간합니다.
7. Dashboard의 Realtime 설정에서 private channel 사용이 허용되어 있는지, homes가 publication에 포함되어 있는지 확인합니다. SQL이 publication 등록 및 private 메시지 정책을 포함합니다.

집 연결 시 서버의 집을 불러오며 로컬 집과 합치지 않습니다. 온라인 상태에서는 로컬 데모 저장을 덮어쓰지 않습니다. 로그아웃하면 저장된 로컬 집으로 복귀합니다. 집 데이터는 항목/배치/문/조명으로 분리된 JSONB로 원자적으로 저장합니다. 이동은 DB에 기록하지 않습니다. 단일 JSONB 행은 MVP 단위이며 향후 가구/에셋/배치별 테이블로 분리할 수 있습니다.

## 권한 및 동시성

- 모든 집/멤버/초대 테이블에 RLS. 집 SELECT는 멤버만 가능, 변경은 멤버 검사 RPC만 허용.
- 서버의 두 슬롯 유니크 제약과 집 행 잠금으로 세 번째 계정 차단.
- 초대는 192비트 랜덤 토큰, 서버에는 SHA-256 해시만 보관. 24시간 만료, 1회 사용, 재발급하면 기존 코드 폐기.
- 파일은 private furniture bucket, 집 UUID 폴더의 멤버만 읽기/업로드/삭제. 미리보기는 1시간 서명 URL 사용.
- 저장은 서버 버전 비교. 충돌 시 저장 오류를 알리고 서버 상태를 다시 불러옵니다. 마지막 변경을 조용히 덮어쓰지 않습니다. 충돌한 로컬 편집은 재적용해야 합니다.
- 업로드는 클라이언트에서 사진 MIME/5MB, GLB magic/15MB 검사, 저장소에서 MIME/15MB 제한. 서버에서 GLB를 해석하거나 악성 콘텐츠 스캔을 제공하지 않습니다.

## 검증 결과

- `npm run build`: TypeScript 및 Vite 빌드 통과.
- `npm test`: 24개 통과. 외벽/가구 충돌, 열린/닫힌 문, 불가 배치, 회전 경계, 두 방의 진입 통로 확인.
- 브라우저 WebGL 렌더링, 포인터 잠금, iOS Safari/Android Chrome 실제 터치 조작: **미검증**. 관리 환경의 지정된 브라우저 제어 도구가 제공되지 않아 수행하지 못했습니다.
- Supabase SQL 실제 적용, 이메일 인증, 두 계정 동시 접속, RLS 공격 시나리오, 재접속, Storage 업로드: **미검증**. 프로젝트 URL/키가 제공되지 않았습니다. 연결 코드를 작성한 상태를 통합 검증 완료로 간주하지 않습니다.

온라인 확인 시 A/B가 각각 이동/앉기/눕기/감정표현 → 가구 변경 → 새로고침 → B 접속 해제 → 재접속 순으로 확인하세요. 세 번째 계정 C는 home SELECT가 빈 결과이고 save_home/Storage/Realtime 접근은 거절되어야 합니다. A/B가 같은 버전에서 동시에 저장하면 하나는 거절되어야 합니다.

## 구현 범위와 한계

구현: 12×10m 두 독립 방, 거실/주방/욕실/현관 영역, 벽·문·바닥·천장, 기본 인테리어, 1인칭 PC/터치 이동과 경량 AABB 충돌, 별도 편집 카메라, 사진 컬렉션 CRUD, GLB 연결, 배치 미리보기/이동/회전/크기/삭제/유효성 검사/영구 저장, Supabase Auth/초대/Presence/Broadcast/배치 버전 저장 경로와 SQL.

부분 구현: 자체 제작 SD 캐릭터는 머리·눈·헤어·의상 및 걷기/앉기/눕기/인사 모션이 있으나 리깅된 아트 에셋 수준이 아닙니다. 두 계정의 슬롯에 따라 머리와 옷 색이 다릅니다. 소파 좌석 분리는 단순 양쪽 좌석이며 이용 잠금은 Broadcast 상태 기반이므로 같은 순간의 동시 착석을 서버에서 원자적으로 막지는 않습니다. 정교한 몸-가구 IK는 없습니다. 모든 가구 충돌은 회전한 외접 사각형이므로 비스듬한 가구에 보수적으로 적용됩니다. 문 열림은 즉시 전환합니다.

그래픽: 기본 가구는 자체 제작 파라메트릭 메시와 승인된 CC0 모델을 함께 사용합니다. 외부 에셋 라이선스는 THIRD_PARTY_ASSETS.md에 기록합니다. 따뜻한 색, 둥근 모서리, 그림자, 마룻바닥을 적용했지만 **요청한 건축 시각화 수준의 사실적 그래픽에는 미달합니다.** 창문/욕실/현관 소품과 외부 풍경도 단순화되어 있습니다. 고품질 GLB 교체로 개선할 구조입니다.

알려진 문제: 초기 Three.js 번들이 큽니다. 모바일 실기기 성능 수치 및 품질 자동 조절은 아직 없습니다. 장시간 열어 둔 서명 URL은 만료될 수 있어 컬렉션을 다시 열어야 합니다. 삭제한 온라인 가구의 Storage 파일은 자동 수거하지 않으므로 Dashboard에서 고아 파일 정리가 필요합니다. 보관 데이터 구조는 클라이언트 형식이며 서버 JSON Schema 수준의 필드별 검증은 후속 강화가 필요합니다. 전체 화면 그래픽 오류 시 다시 불러오기 안내를 제공합니다.

미구현: 정식 3인칭(카메라 인터페이스만), AI 사진→3D, 의상 커스터마이징, 추억/메모/편지. `PhotoReconstructionProvider`는 향후 연결용 인터페이스이며 UI에 동작하는 기능으로 표시하지 않습니다.

다음 우선순위: 실제 Supabase 통합·권한 테스트 → 브라우저 및 모바일 조작 테스트 → 좌석 서버 잠금/안전한 상호작용 정렬 → 그래픽 에셋 교체와 조명 개선 → 업로드/고아 파일 수명 관리 → 모델 캐싱 및 모바일 품질 단계.

## Cloudflare Pages (현재 배포하지 않음)

후속으로 사용자가 배포를 승인한 경우 build command `npm run build`, output directory `dist`, 위 VITE 환경변수를 설정합니다. 서비스 역할 키는 필요하지 않습니다. 무료 티어 DB/Realtime 동시접속/Storage/egress 한도를 Dashboard에서 확인하고 GLB/사진 크기를 제한하세요. 무료 범위의 영구 제공을 보장하지 않습니다.

## 가구·재질 업데이트 — 2026-11-10

승인된 CC0 가구 2개와 PBR 재질 3개를 번들에 추가했습니다. 원목 라운지 체어는 컬렉션에서 여러 번 배치할 수 있습니다. 새 데모에는 기본 배치되며, 기존 저장 공간에는 컬렉션 항목만 추가해 사용자 배치를 바꾸지 않습니다. 기존 기본 테이블은 사용자 사진이나 연결한 모델이 없는 경우에만 교체됩니다. 삭제한 제공 가구는 이후 재접속에서 되살리지 않습니다.

가구의 사진, 모델(`model`), 모델 출처(`modelAsset`), 치수(`size`), 배치(`placements`)를 분리합니다. 사진만 등록 → 추후 수정에서 GLB 업로드 → 기존 가구의 모든 배치에 새 모델 반영이 가능합니다. 재구성한 모델도 동일한 연결 경로를 사용할 수 있으며 자동 AI 생성은 아직 미구현입니다.

라이선스·제작자·가공 방식은 [THIRD_PARTY_ASSETS.md](THIRD_PARTY_ASSETS.md)에 기록했습니다. 모델의 외부 파일 의존성 제거, 파일 해시, 기존 사용자 데이터 보존을 추가로 자동 테스트합니다. 브라우저와 모바일 실기기 검증은 여전히 미검증입니다.

## 둥근 UI 적용 — 2026-11-10

승인한 디자인 시안을 기준으로 크림색 둥근 메뉴, 살구색 주요 버튼, 연두색 선택 표시, 하단 메뉴, 둥근 가구 카드를 적용했습니다. PC 컬렉션은 오른쪽 플로팅 패널, 모바일 컬렉션은 하단 메뉴 위의 패널입니다. 가구 등록·수정·삭제, 조감도 보기 → 인테리어 하기, 생활 상호작용은 기존 기능을 유지합니다. 생성한 시안 이미지를 집의 배경으로 사용하지 않으며 실제 Three.js 공간을 계속 렌더링합니다.

마우스 잠금 실패를 모두 브라우저 미지원으로 표시하지 않도록 수정했습니다. API 부재·창 포커스·명시적인 임베드 보안 오류·권한 거절·원인 미상을 구분하며, 재시도와 새 탭 열기·드래그 선택을 제공합니다. 오류 안내 개선이 브라우저의 권한 제한을 해제하는 것은 아닙니다. 현재 사용자 브라우저에서 실패한 정확한 이유는 아직 확인하지 못했습니다.

전체 브라우저 렌더링·포인터 잠금·모바일 터치 조작은 지정된 브라우저 제어 도구가 없어 미검증입니다.

## FPS 시야·조감도 업데이트 — 2026-11-10

PC에서는 화면 클릭 시 Pointer Lock으로 FPS처럼 마우스를 따라 시야가 회전합니다. ESC로 마우스 잠금을 해제하고 메뉴를 사용할 수 있습니다. 메뉴 열기·생활 모드 종료 시에도 잠금을 해제합니다. 잠금 실패는 원인별 안내와 재시도·새 탭 열기·드래그 선택을 제공합니다. 모바일은 이동 조이스틱 + 화면 드래그를 유지합니다.

조감도 보기와 인테리어 편집은 별도 모드입니다. 조감도는 가구를 선택·변경하지 않으며, 인테리어 하기로 편집에 진입합니다. 편집 완료 시 조감도로 복귀하고 둘러보기로 이전 생활 위치에 돌아갑니다. 모드 변경 시 이동 입력을 초기화합니다.

터치·대체 드래그 입력의 포인터 소유·종료·취소 동작을 자동 테스트합니다. 실제 PC/모바일 브라우저 및 인앱 브라우저의 Pointer Lock 권한·터치·렌더링 검증은 지정된 브라우저 제어 도구가 없어 미검증입니다.

## 시안 정렬과 안내 자동 닫기 — 2026-11-10

마우스 잠금 안내와 일반 알림은 4.5초 표시 후 260ms 동안 아래로 내려가며 사라집니다. 안내가 교체되거나 직접 닫히면 이전 타이머를 정리합니다. 주기적인 상호작용 문구 갱신으로 타이머가 다시 시작되지 않습니다. 첫 조작 도움말도 4.5초 후 숨깁니다. 잠금 재시도와 조작 선택은 설정에서 다시 사용할 수 있습니다.

시안에 맞춰 화면의 둥근 테두리, 하단 메뉴 크기와 위치, 330px 가구 패널, 가운데 정렬한 가구명·배치 버튼, 주요 카테고리 순서를 조정했습니다. 수정·삭제·등록자·치수는 각 가구의 정보·수정 메뉴에 있습니다. 기본 가구에는 유형별 대표 3D 미리보기를 제공하며 원본 사용자 사진과 구분합니다. 이 미리보기는 웹의 절차적 기본 가구 유형에 대응하는 대표 이미지로, 개별 사용자가 지정한 치수나 커스텀 모델의 실시간 렌더가 아닙니다. 사용자가 올린 사진은 우선 표시합니다.

이 변경은 생성된 시안의 인테리어 이미지를 배경에 붙이지 않습니다. 실제 3D 집은 계속 탐색 가능하며 시안의 사실적인 배경과 동일한 그래픽 수준을 달성한 상태는 아닙니다. 브라우저 시각 검증과 실제 FPS 동작은 아직 미검증입니다.

## GitHub Pages — 같은 저장소 사용

GitHub 저장소는 `minho-nim/minoom` 하나를 사용합니다. `main`은 원본 소스, `gh-pages`는 실행용 정적 파일만 담는 브랜치입니다. 원본 비공개 설정은 자동으로 변경하지 않습니다. GitHub Free에서 비공개 저장소의 Pages는 지원하지 않으며, Pages 관리 권한도 필요합니다.

프로젝트 경로용 빌드: `VITE_BASE_PATH=/minoom/ npm run build`. 번들 JS·CSS·폰트 및 런타임 모델·재질 경로가 `/minoom/` 아래에서 동작하도록 구성했습니다. 저장된 기본 모델 경로는 변경하지 않습니다. 기존 Sites 루트 배포용은 `npm run build`를 사용합니다.

GitHub Settings → Pages → Deploy from a branch → `gh-pages` / `(root)`를 선택하면 GitHub가 배포합니다. 정상 활성화 후 주소는 `https://minho-nim.github.io/minoom/`입니다. 이 문구만으로 실제 배포가 완료됐다는 의미는 아닙니다.
